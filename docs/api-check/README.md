# Пакет для проверки собственного API

- Базовый HTTPS-адрес: `https://111-88-243-251.sslip.io/api/v1`
- OpenAPI 3.0: [openapi.json](openapi.json)
- Конфигурация обязательных сценариев: [DATA-API.yaml](DATA-API.yaml)
- Исходные тестовые данные: [test-data.json](test-data.json)

## Тестовые учётные записи

Нужны **два разных аккаунта MAX**: гид и гость. Отдельной регистрации, паролей и административной роли API не предусматривает. Войдите каждым аккаунтом через [бота Маяк](https://max.ru/t501_hakaton_max_bot) и запустите мини-приложение. Подписанное `window.WebApp.initData` гида и гостя передавайте в `x-max-init-data` для соответствующих запросов. Оно действительно не более часа; перед новой проверкой получите свежие данные запуска. Передавать токен бота проверяющему не требуется.

Аккаунт гида сначала создаёт профиль через `PUT /professional/profile`; после этого он может публиковать экскурсии. Гость бронирует опубликованную экскурсию. Гид не может забронировать собственную экскурсию. У этих ролей нет отдельных паролей или API-ключей.

## Порядок воспроизводимой проверки

1. Проверьте `GET /health`.
2. Получите свежие `initData` двух MAX-аккаунтов. Проверьте их через `POST /auth/max`.
3. Создайте профиль гида из `test-data.json`.
4. Подставьте в `scheduleSlots` дату **после текущего дня** по времени Москвы, затем создайте экскурсию. Сохраните `id` ответа.
5. Получите экскурсию по `GET /experiences/{id}` и проверьте наличие в `GET /experiences?cityId=saint-petersburg`.
6. Замените `experienceId` и `date` в блоке бронирования, отправьте его от имени гостя. Сохраните `id` бронирования.
7. Проверьте `GET /bookings` от имени гостя, затем отмените тестовое бронирование через `DELETE /bookings/{id}`.
8. Проверьте, что `GET /bookings` без заголовка авторизации возвращает 401.

`test-data.json` — шаблон запросов, а не данные, уже загруженные в production. Постоянные данные создаются указанными методами API. Веб-клиент содержит локальные демонстрационные материалы, но API отдаёт только опубликованные экскурсии из PostgreSQL.

Публичный адрес взят из корневого README. `GET /health` был проверен 30.09.2026 и вернул HTTP 200; перед внешней проверкой доступность можно повторно проверить командой `curl --fail https://111-88-243-251.sslip.io/api/v1/health`.

```bash
pnpm --filter @marketplace/api build
node apps/api/scripts/export-openapi.mjs
```
